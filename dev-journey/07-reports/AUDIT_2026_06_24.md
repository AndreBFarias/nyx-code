## 2. Achado central -- bug #1 "limitado a pasta padrao" (CONFIRMADO no codigo)

**Sintoma relatado:** "ele esta limitado a pasta padrao e não tem leitura do resto; a ideia e ele ter
leitura de tudo e saber usar cada feature de forma independente."

**Causa-raiz (verificada lendo o codigo, não suposta):** o acesso a arquivos **ja e livre por design**
(ONDA-37, `NYX_SANDBOX_STRICT` desligado por default) -- `validate_path` em `nyx/agent/tools/base.py:182-193`
libera qualquer pasta e so bloqueia segredos (`.ssh/.gnupg/.aws`). O problema esta nos **tools de
descoberta**, que filtram o resultado contra o `project_root` do boot:

- `nyx/agent/tools/glob_tool.py:36,42` -- `project = Path(project_root).resolve()` e o comprehension
  `if p.is_file() and p.resolve().is_relative_to(project)`. **Fora da raiz retorna vazio.** Pior: usa o
  `project_root` recebido por argumento (raiz do boot), não o `_ACTIVE_ROOT` que segue o `/cd`.
- `nyx/agent/tools/search.py:102` -- `f.relative_to(root)` no fallback Python (`_search_walk`) quebra fora
  da raiz; mitigado quando `rg`/`grep` existem (caso comum), pois o caminho rapido não filtra.
- `nyx/agent/tools/list_files.py:44` -- **tem** fallback para path absoluto (`... if e.is_relative_to(root)
  else str(e)`), entao funciona fora da raiz. E a referencia do comportamento correto.

**Efeito pratico:** `read_file` por caminho absoluto funciona, mas o agente **não consegue
explorar/listar/buscar** fora da pasta padrao -> sensacao de "limitado". Isto **viola o ADR-009 (acesso
universal) que ja existe** -- o fix restaura conformidade, não cria politica nova.

**Segundo eixo (autonomia):** o modelo 3B **não sabe** que pode operar fora da raiz, porque as descricoes
dos tools dizem "padrao: raiz do projeto" e o system prompt não instrui exploracao livre do FS. Por isso o
fix tem duas metades: (a) codigo dos discovery tools; (b) descricoes dos tools + diretiva de prompt.

> Mapeado para **ONDA-45** (sprints 370/371/372).

## 3. Achados por dimensao (resumo) e mapeamento para sprint

### D1 -- Arquitetura & estado
Stack em 4 camadas (`run.sh` -> Ollama :11435 -> Proxy :11436 think-adaptativo -> CLI/AgentLoop com 35
tools, 67 commands, 15 services). Backlog tecnico zerado; so `SPRINT_RELEASE_V1_3_4_CUT_01` aguarda corte
humano. 34 ADRs vigentes. Gaps não-de-codigo: GPU OOM residual de ambiente (CPU fallback funciona,
ADR-032/033), snapshot de docs defasado (2026-05-21).

### D2 -- Acesso a arquivos
Ver secao 2. Achado tambem: `run_command` roda com `cwd=project_root` mas leitura via shell e irrestrita
(esperado). Escalonamento de roots via `/sandbox add` e por design (ação do usuario).
-> **ONDA-45**.

### D3 -- Autonomia de tools
AgentLoop solido (parser 7 niveis, deteccao de repeticao, permissões 4 niveis, compactacao de contexto).
Gaps: sem cache de resultado de tool entre iteracoes; sem circuit-breaker para tool que falha repetido; cap
de 5 tools por VRAM pode esconder tool necessaria; parser fallback sem contexto multi-step.
-> **candidatos pendentes de evidencia de onda** (so viram spec se a Onda de validação 1, pos-45, mostrar o
agente falhando). Anti-debito: ficam listados no MASTER.

### D4 -- Troca de model & infra
Troca ja existe (`--3b/--4b/--model`, `NYX_MODEL`, `config.toml`), mas e invisivel, exige restart, sem
fallback se o pull falhar, e suporte a "think" e hardcoded so para `qwen3` (`MODELS_SUPPORTING_THINKING` em
`defaults.py:61`). `DEFAULT_MODEL = qwen2.5-coder:3b`. A infra que "faz model ruim ficar bom": intent
classifier + think-adaptativo + budget de output por intent + guardrails + OOM cascade GPU->GPU//2->CPU.
validação empirica (ADR-031): a infra eleva modelos tool-capable non-thinking (qwen2.5-coder 96.8), não
modelos thinking-only (qwen3:4b 34.6) -- selecao de modelo ainda importa.
-> **ONDA-47** (gerenciador completo, decisao do dono).

### D5 -- Gauntlet / baterias de teste
61 fases, zero mocks (ADR-010), baselines recentes 19/19 (fase rapida). **Cobertura faltante para
produção:** acesso a path arbitrario (o proprio bug #1!), troca de model E2E, tool-chaining multi-turno
(T-10 não-mapeado), casos de borda, guardrails de regressao de performance (sem limites enforced).
-> teste do bug #1 entra em **ONDA-45.3**; o resto em **ONDA-48**.

### D6 -- CI / build / versao / working tree
- **BLOCKER:** `.github/workflows/anonymity-check.yml:66-75` tem um `fi` orfao (falta o `if` antes do
  `echo` da linha 73) -> erro de sintaxe bash; trava o job e qualquer push se for required check.
  **Confirmado lendo o arquivo.**
- `ci.yml` (smoke) aparenta assertar `qwen3:4b` enquanto `DEFAULT_MODEL` real e `qwen2.5-coder:3b` --
  divergencia a verificar/corrigir.
- Versao: `nyx/__version__.py = 1.3.4`, mas tags git param em `v1.1.1` (sem v1.2/v1.3). Versionamento
  manual, sem pre-commit ativo (hooks em backup `.bak`), sem `.pre-commit-config.yaml`.
- Build: so `install.sh` (clone + install local). Sem wheel/sdist, sem AppImage/Flatpak/deb, sem CI de
  release.
- Working tree: 6 baselines `.json` do gauntlet untracked + 2 modificados; `.gitignore` cobre `*.md` mas
  não os `*.json` de baseline.
-> CI e working tree em **ONDA-46**; distribuicao e release em **ONDA-49**.
